# VIA API Specification

The live, authoritative contract is the OpenAPI document generated by FastAPI:
`/api/openapi.json` (interactive docs at `/api/docs`; both disabled when
`VIA_ENABLE_DOCS=false`). This page records conventions and status.

## Conventions
- **Versioning:** every endpoint is under `/api/v1`. Breaking changes get `/api/v2`.
- **Transport:** JSON (`application/json`); uploads use `multipart/form-data`.
- **Browser access:** same-origin through the web app's `/api/*` proxy. Programmatic clients may call the API directly.
- **Authentication:** session cookie `via_session` (`httpOnly`, `SameSite=Lax`, `Secure` in production, 14-day expiry) or `Authorization: Bearer <session token>` (obtained with `login` + `issue_token: true`).
- **CSRF:** every `POST/PATCH/PUT/DELETE` under `/api/v1` must send `X-VIA-Request: 1` unless it uses Bearer auth; otherwise `403 csrf_failed`. The typed client does this.
- **Request IDs:** send `X-Request-ID` (8–64 chars of `[A-Za-z0-9-]`) or one is generated; it's echoed in the response header and in error bodies.
- **Pagination:** `?limit=` (default 25, max 100) and `?offset=`; list responses are `{ "items": [...], "total": n, "limit": l, "offset": o }`.
- **Timestamps:** ISO 8601, UTC. **IDs:** UUIDs.

### Error envelope
Every non-2xx response:

```json
{ "error": { "code": "not_found", "message": "Project not found", "details": null, "request_id": "4f0c..." } }
```

| Status | `code` | When |
|---|---|---|
| 400 | `bad_request` | Malformed request |
| 401 | `unauthorized` / `invalid_credentials` | Missing, invalid, expired or revoked session; failed login |
| 403 | `forbidden` / `csrf_failed` | Role too low on a project you can see; missing CSRF header |
| 404 | `not_found` | Unknown route or resource, **or** a resource the caller may not see |
| 405 | `method_not_allowed` | |
| 409 | `conflict` / `duplicate_file` / `not_parsed` / `project_archived` | State conflicts |
| 411 | `length_required` | Upload without Content-Length |
| 413 | `payload_too_large` | Upload over `VIA_MAX_UPLOAD_BYTES` |
| 415 | `unsupported_file_type` | Not a supported PCB file |
| 503 | `storage_unavailable` / `queue_unavailable` | Dependency down |
| 422 | `validation_error` | Body/query validation failed; `details` lists `{loc, message, type}` |
| 429 | `rate_limited` | Rate limit exceeded; `details.retry_after_seconds` |
| 500 | `internal_error` | Unexpected error; details are logged with the request id, never returned |

### Security headers (all responses)
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy`, and `Cache-Control: no-store` on `/api/v1/*`.
CORS allows only `VIA_CORS_ORIGINS`.

## Endpoints

Roles: **any** = signed in; project roles **viewer < editor < owner** (see DATABASE.md).
A project you can't see always returns `404`; a project you can see but lack the role for returns `403`.

### Health
| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/v1/health` | none | Liveness: `{status, version}` |
| GET | `/api/v1/health/ready` | none | Readiness: database (incl. migrations at head), Redis, object storage. `200` when all are OK, `503` with the same body otherwise. Failure `detail` is an error class name only. |

### Auth (`/api/v1/auth`)
| Method | Path | Auth | Rate limit | Description |
|---|---|---|---|---|
| POST | `/register` | none | 10/h per IP | `{email, password, display_name}` → `201` + session cookie. Creates a personal organization. `409 email_taken`, `422 weak_password` |
| POST | `/login` | none | 20/min per IP, 8/5 min per account | `{email, password, issue_token?}` → session cookie (or `session_token` in the body with `issue_token: true`, for Bearer clients). Same `401 invalid_credentials` for unknown email and wrong password |
| POST | `/logout` | any | | Revokes the current session, clears the cookie |
| GET | `/me` | any | | `{user, organizations[]}` |
| GET | `/sessions` | any | | Your active sessions (`current` flags this one) |
| DELETE | `/sessions/{id}` | any | | Revoke one of your sessions → `204`; other users' sessions are `404` |
| POST | `/password-reset/request` | none | 5/h per IP | `{email}` → always `202` with the same message (no account enumeration) |
| POST | `/password-reset/confirm` | none | 5/h per IP | `{token, new_password}`; single-use, expiring token; revokes all sessions. `400 invalid_reset_token` |

### PCB upload and parsed data (`/api/v1/pcb`)
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/limits` | any | `{max_upload_bytes, formats[{id, name, extensions}]}` for client-side validation. Since Stage 2: includes `{id: "kicad_project", name: "KiCad project (.zip)", extensions: [".zip"]}` |
| POST | `/import` | editor (60/h) | `multipart/form-data`: `project_id`, `file`, optional `design_id` (new revision) or `name` (new design). Stores the file and returns **`202`** `{design, revision}` with `revision.status = pending`; parsing runs in the worker. Errors: `411 length_required` (no Content-Length), `413 payload_too_large` (checked before and while reading), `415 unsupported_file_type` (extension + header sniff), `422 empty_file`, `422 invalid_project_archive` (a `.zip` that isn't a usable KiCad project: no board, several boards, unsafe paths, zip bomb, board over the size limit; the message says which), `409 duplicate_file` (same SHA-256 already in the project and not failed; `details` has the existing `design_id`/`revision_id`), `409 project_archived`, `503 storage_unavailable` / `queue_unavailable` (revision marked failed) |
| GET | `/{design_id}` | viewer | Board summary of the current parsed revision (`?revision_id=` for another): source info (incl. `board_file`/`project_files` for archives), title, constraints (incl. `rules_source`, `rules`, `net_classes`, `custom_rules`), geometry (bbox, size, area, thickness, copper layers), stats, warnings. `409 not_parsed` if no parsed revision |
| GET | `/{design_id}/normalized` | viewer | The complete normalized `PCBDesign` JSON (`Content-Encoding: gzip`) |
| GET | `/{design_id}/components` | viewer | Paginated; `q` (reference/value/footprint), `side` = `top`\|`bottom`; natural sort by reference (R2 before R10) |
| GET | `/{design_id}/nets` | viewer | Paginated; `q`; per-net pad/track/via counts and track length |
| GET | `/{design_id}/layers` | viewer | All layers in file order with kind and side |

### Designs, revisions, files
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/api/v1/designs?project_id=` | viewer | Designs with `current_revision` (latest parsed) and `latest_revision` (latest upload, any status) |
| GET | `/api/v1/designs/{id}` | viewer | Plus all `revisions` (newest first) |
| PATCH | `/api/v1/designs/{id}` | editor | `{name?, description?}` |
| DELETE | `/api/v1/designs/{id}` | editor | Deletes revisions, parsed rows **and stored objects** → `204` |
| GET | `/api/v1/revisions/{id}` | viewer | Poll this after upload: `status` = `pending` → `processing` → `ready` \| `failed`; `warnings`, `object_counts`, `error_code`/`error_message`, parser and schema versions, `imported_at`, source file metadata |
| GET | `/api/v1/files?project_id=` | viewer | Original uploads: name, size, SHA-256, design and revision |
| GET | `/api/v1/files/{id}/download` | viewer | The original bytes as `application/octet-stream` + `Content-Disposition: attachment` |

Deleting a project also deletes its stored objects.

### Analysis and findings (Stage 2, Milestone 2)
See docs/FINDINGS_SYSTEM.md for the finding contract. Reading needs viewer access, starting and reviewing need editor access; anything inaccessible is `404`.

| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/analysis/checks` | any | Available checks: `{id, version, category, title, description, source}` |
| POST | `/designs/{design_id}/analysis-runs` | editor (60/h) | Body `{revision_id?, checks?}` (default: current parsed revision, all checks). **`202`** with the queued run; if an identical analysis is already queued/running for that revision, **`200`** with it (no new run). Errors: `409 not_parsed`, `409 project_archived`, `422 unknown_check`, `503 queue_unavailable` (run marked failed) |
| GET | `/designs/{design_id}/analysis-runs` | viewer | Paginated run history across revisions, newest first |
| GET | `/analysis-runs/{run_id}` | viewer | Status (`queued`/`running`/`succeeded`/`failed`), attempt, config, per-check results `[{check_id, version, status, finding_count, duration_ms, message}]`, summary `{finding_count, by_severity, checks, duration_seconds}`, analysis/engine/parser/schema versions, safe error |
| GET | `/analysis-runs/{run_id}/findings` | viewer | Filters (comma-separated lists): `severity`, `category`, `source`, `verification`, `status`; plus `check_id`, `component`, `net`, `q` (title, description, components, nets; LIKE metacharacters literal). `sort` = `severity` (default) \| `category` \| `title` \| `check` \| `status` \| `confidence`, `order`, `limit` ≤ 200, `offset`. Returns `{items, total, limit, offset, facets}` with counts per severity/status/category/source for the whole run. `422 invalid_filter` for unknown values |
| GET | `/findings/{finding_id}` | viewer | Finding with `evidence[]` and review `history[]` |
| POST | `/findings/{finding_id}/review` | editor | `{status: open\|reviewed\|dismissed, reason?}`; `422 reason_required` when dismissing without a reason. Appends to the history |
| GET | `/designs/{design_id}/analysis-compare?base_run_id=&target_run_id=` | viewer | `{base_run, target_run, new, resolved, persisting}` by fingerprint. Both runs must be finished runs of this design (`404` otherwise; `409 run_not_finished`) |

### Manufacturing profiles and analysis options (Milestone 3)
| Method | Path | Role | Description |
|---|---|---|---|
| GET | `/projects/{project_id}/manufacturing-profiles` | viewer | Built-in VIA profiles (`via-conservative`, `via-advanced`) then the project's: `{key, name, description, source, builtin, values}` |
| POST | `/projects/{project_id}/manufacturing-profiles` | editor | `{name, description?, values{min_track_width, min_clearance, min_drill, min_via_diameter, min_annular_ring, min_hole_to_hole, min_copper_to_edge, min_silk_width}}` (mm, > 0) → `201`; `409 profile_exists` |
| PATCH | `/manufacturing-profiles/{profile_id}` | editor | Edit name, description or values (future runs only) |
| DELETE | `/manufacturing-profiles/{profile_id}` | editor | `204` |

`POST /designs/{id}/analysis-runs` also accepts:

```
options {
  profile?,                              # key from the list above
  power?: {nets{net: amps}, temperature_rise_c?, copper_thickness_mm?},
  impedance?: {nets{net: ohms}, tolerance_pct?},
  decoupling_max_distance_mm?
}
```

- `422 unknown_profile` for a key that isn't built in or belongs to another project.
- The run's `config.options.manufacturing_profile` holds the exact values used.
- Run `checks[].details` carry per-check facts (e.g. `kicad_drc`: KiCad version, rules, suppressed environment checks).
