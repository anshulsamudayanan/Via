# VIA API Specification

The live, authoritative contract is the OpenAPI document generated by FastAPI:
`/api/openapi.json` (interactive docs at `/api/docs`; both disabled when
`VIA_ENABLE_DOCS=false`). This page records conventions and status.

## Conventions
- **Versioning:** every endpoint is under `/api/v1`. Breaking changes get `/api/v2`.
- **Transport:** JSON (`application/json`); uploads (CP4) use `multipart/form-data`.
- **Browser access:** same-origin through the web app's `/api/*` proxy. Programmatic clients may call the API directly.
- **Authentication (CP3):** session cookie (`httpOnly`, `SameSite=Lax`, `Secure` in production) or `Authorization: Bearer <session token>`.
- **CSRF (CP3):** cookie-authenticated `POST/PATCH/PUT/DELETE` must send `X-VIA-Request: 1` (the typed client does this).
- **Request IDs:** send `X-Request-ID` (8–64 chars of `[A-Za-z0-9-]`) or one is generated; it's echoed in the response header and in error bodies.
- **Pagination (CP3+):** `?limit=` (default 25, max 100) and `?offset=`; list responses are `{ "items": [...], "total": n, "limit": l, "offset": o }`.
- **Timestamps:** ISO 8601, UTC. **IDs:** UUIDs.

### Error envelope
Every non-2xx response:

```json
{ "error": { "code": "not_found", "message": "Project not found", "details": null, "request_id": "4f0c..." } }
```

| Status | `code` | When |
|---|---|---|
| 400 | `bad_request` | Malformed request |
| 401 | `unauthorized` | Missing/invalid session (CP3) |
| 403 | `forbidden` | Authenticated but not allowed (only where existence is already known) |
| 404 | `not_found` | Unknown route or resource, **or** a resource the caller may not see |
| 405 | `method_not_allowed` | |
| 409 | `conflict` | e.g. duplicate upload (CP4) |
| 413 | `payload_too_large` | Upload over `VIA_MAX_UPLOAD_BYTES` (CP4) |
| 415 | `unsupported_media_type` | Unsupported file type (CP4) |
| 422 | `validation_error` | Body/query validation failed; `details` lists `{loc, message, type}` |
| 429 | `rate_limited` | Rate limit exceeded (CP3) |
| 500 | `internal_error` | Unexpected error; details are logged with the request id, never returned |

### Security headers (all responses)
`X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Cross-Origin-Opener-Policy: same-origin`, `Permissions-Policy`, and `Cache-Control: no-store` on `/api/v1/*`.
CORS allows only `VIA_CORS_ORIGINS`.

## Endpoints

### Implemented (CP2)
| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/api/v1/health` | none | Liveness: `{status, version}` |
| GET | `/api/v1/health/ready` | none | Readiness: database (incl. migrations at head), Redis, object storage. `200` when all are OK, `503` with the same body otherwise. Failure `detail` is an error class name only (no hosts or credentials). |
