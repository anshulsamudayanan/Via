# VIA Security & Privacy

Status: updated at Checkpoint 5. Items are marked ✅ (implemented and tested)
or *(planned, CPn)*.

## Threat model (Stage 1)
| Asset | Threats | Controls |
|---|---|---|
| User accounts | Credential stuffing, brute force, session theft | Argon2id hashing (rehash on parameter change), 10–128 char passwords ✅; identical response and equalized hashing time for unknown email vs wrong password ✅; Redis rate limits on login (per IP and per account), register, password reset, password change, member lookup ✅; httpOnly + SameSite=Lax (+ Secure in production) session cookie ✅; server-side sessions storing only SHA-256 token hashes, 14-day expiry, revocable per device, all revoked on password reset and others on password change ✅ |
| Password reset | Token theft, enumeration | 256-bit single-use tokens (hash stored), 60-minute expiry, all outstanding tokens invalidated on use ✅; request endpoint always answers the same ✅; reset page sends no `Referer` ✅; no email provider in Stage 1: dev logs the link, production doesn't send ✅ |
| Private projects | IDOR / cross-user access, enumeration | One authorization service (`services/access.py`) used by every project-scoped route ✅; inaccessible projects return `404` identical to non-existent ones ✅; organization and project membership enforced independently ✅; lists, search, counts and activity filtered through the same rule ✅; security regression suite (`tests/integration/test_access_control.py`) ✅ |
| Upload pipeline | Malicious files, resource exhaustion, path traversal | Content-Length required and checked before the body is read (411/413), bytes re-counted while reading ✅; extension + header sniff (415), empty files rejected ✅; SHA-256 computed server-side, verified again by the worker before parsing ✅; server-generated storage keys, sanitized display filenames ✅; every attempt (accepted, rejected, duplicate) recorded in `upload_records` + activity ✅; uploads rate limited (60/h per user) ✅ |
| Parser | Hostile or pathological files, parser bugs | Files are never executed; pure-Python, non-recursive tokenizer, warning caps ✅. Parsing never runs in the API or worker process: worker spawns `python -I -B -m via_pcb.cli` with an **empty environment** (no DB URL, storage keys or secret key), rlimits (CPU = timeout, address space 3 GiB default, `RLIMIT_FSIZE=0` no file writes, `RLIMIT_NPROC=0` no new processes for non-root users, 64 fds, no core dumps), wall-clock timeout, own session, empty temp cwd; output validated against the schema; stderr logged, never returned ✅ (`tests/unit/api/test_parser_sandbox.py`) |
| Object storage | Public exposure, path traversal | Private bucket (no public policy) ✅; credentials only in server env, never sent to the browser (the browser only talks to the web origin) ✅; keys generated by the server and validated against a strict pattern, `..`/absolute paths rejected ✅; local backend refuses keys escaping its root and writes atomically ✅; downloads via the API after authorization *(CP4)* |
| Database | SQL injection, integrity | SQLAlchemy parameterized queries only ✅; CHECK constraints on enums, FKs, unique constraints ✅; `projects.visibility` defaults to `private` at the database level ✅ |
| Browser | CSRF, XSS, clickjacking | Same-origin API via rewrite ✅; CSP (`default-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`) ✅; `X-VIA-Request: 1` required on every unsafe `/api/v1` request without Bearer auth (blocks CSRF incl. login CSRF) ✅; React escaping (the only `dangerouslySetInnerHTML` is a constant theme script) ✅; strict CORS allowlist ✅ |
| Secrets | Leakage | Only environment variables ✅; `.env` git-ignored ✅; `.env.example` placeholders only ✅; Compose refuses to start without required secrets ✅; production settings reject default/short `VIA_SECRET_KEY`, wildcard CORS and bucket auto-creation ✅; `SecretStr` keeps secrets out of logs and reprs ✅; build-time CA secret never stored in image layers ✅ |
| Errors | Information disclosure | Consistent error envelope ✅; unexpected errors logged with a request id and returned as generic 500 ✅; readiness failures report only an error class name ✅ |
| Containers | Privilege | API, web and MinIO images run as non-root users ✅; datastores bound to 127.0.0.1 on the host ✅ |

## Audit logging ✅
`activity_logs` records: registration, login success and failure (failure for unknown
accounts has no actor), logout, session revocation, password change, password reset request
and completion, profile updates, organization creation, project create/update/archive/
unarchive/delete, and member add/role change/remove. IP and user agent are stored for audit
but never returned by the activity API. Secrets are filtered out of `details` by key.
Also recorded: design uploaded / upload rejected (with reason) / parsed / parse failed / renamed / deleted.

## Known trade-offs (Stage 1)
- **Registration reveals whether an email is registered** (`409 email_taken`); mitigated by the per-IP registration limit. Standard for sign-up flows; revisit with email verification.
- **Adding a project member by email reveals whether that email has an account** to project owners; rate limited (30/h per user). Invitations by email would remove this.
- **Rate limiter fails open** when Redis is unavailable (logged; readiness reports Redis down) so a cache outage can't lock everyone out.
- **No email verification yet**; `email_verified_at` exists for it.
- **Next.js buffers proxied upload bodies in memory** (up to the configured `proxyClientMaxBodySize`, ~52 MB) before forwarding them to the API, so concurrent large uploads cost web-server memory. Presigned direct uploads would remove this.
- **`RLIMIT_NPROC` doesn't apply to root**: the containers run as non-root users, so it does in Docker; in a root dev shell it doesn't.
- **`proxy.ts` only checks that a session cookie exists** (fast redirect for signed-out page loads). It's not a security boundary; the API validates every request.

## Privacy & consent
- Uploaded files are **never** automatically contributed to VIA Learn or used for model training.
- `data_consents` records explicit, scoped, revocable consent. No consent is granted by default and Stage 1 has no flow that uses it *(CP2 schema)*.
- AI providers are **disabled by default** (`VIA_AI_PROVIDER=none`): the disabled provider raises on every call and nothing fabricates output in its place ✅.
- API keys only come from the environment, read by the provider SDK; `/ai/status` never exposes them ✅.
- Project data reaches a model only through `ContextProvider` (`via_api/ai/context.py`), which checks project access (404 otherwise) and, for external providers, an active per-project `external_ai_processing` consent granted by the project owner (403 `consent_required` otherwise). Consent is policy-versioned, revocable with immediate effect, and audited ✅.
- The context is a bounded summary from database rows: counts, layers, net names, component list, warnings. No source files, normalized geometry, storage keys, emails or upload hashes; truncation is reported ✅ (`tests/integration/test_ai.py`).
- Refusals raise `AIRefusedError` and are never replaced by invented output ✅. No feature calls a model in Stage 1.

## Future hardening (post Stage 1)
Parser in a separate no-network container (gVisor/Firecracker) instead of a subprocess in the worker container, presigned direct-to-storage uploads (avoids proxy buffering), Postgres row-level security, 2FA/WebAuthn, malware scanning of uploads, signed and expiring download URLs everywhere.
